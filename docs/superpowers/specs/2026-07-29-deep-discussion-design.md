# 设计文档：deep-discussion（合并版「拷问」技能）

- 日期：2026-07-29
- 作者：与用户协作设计（参照 mattpocock/skills 的 grill-me 与 grill-with-docs）
- 状态：设计已确认，待实现

## 1. 背景与目标

用户想参照网上的 `grill-me` 与 `grill-with-docs`（mattpocock/skills 仓库），做一个**自己的合并版技能**。

原版行为：
- `grill-me`：只做一件事——启动一个「 relentless interview（ relentless 拷问式访谈）」来打磨计划/设计。真正的逻辑在一个 `/grilling` 子 agent 里：一次只问一个问题、每题给推荐答案、沿决策树逐枝走、能从环境查到的事实直接查而不问、在用户确认「达成共同理解」前不采取任何行动。
- `grill-with-docs`：同样的拷问，但额外调用 `/domain-modeling` 技能，在聊天过程中**实时**维护两份文档——`CONTEXT.md`（统一语言/术语表）和 `docs/adr/`（架构决策记录 ADR）。

用户的合并版目标：
1. 把两者合为一个技能。
2. **文档产出改为按需**：聊的过程中或聊完后，只有用户明确要求「保存 / 落文档 / 导出」时才把结果写成本地文件；如果用户不要求，就只聊天、不落任何文件（「聊完就完了」）。
3. 文档内容与格式**对齐原版**（`CONTEXT.md` + `docs/adr/`），即「跟它一样」。

## 3. 行为设计

### 3.1 拷问采访循环（核心，全程中文）

技能被 `/deep-discussion` 唤起后，主 agent 进入「griller」角色，遵循以下纪律：

1. **一次一问**：每次只抛**一个问题**，等用户回答后再继续；绝不一次甩多个问题。
2. **每题给推荐答案**：每个问题都附上 agent 的推荐答案，供用户参考或反驳。
3. **沿决策树推进**：走遍每个决策分支，遇到有依赖关系的决策，逐个解开（先解前置依赖）。
4. **事实 vs 决定**：
   - 能从环境获取的事实（读文件、查工具、看代码）——直接查，不要拿去问用户。
   - 「决定」属于用户——必须抛回给用户确认，不可自作主张。
5. **逼精确**：挑战模糊/重载术语，构造边界场景（edge-case）逼用户把概念边界说清。
6. **内部累积草稿（不落盘）**：对话过程中，**只在对话上下文里**维护两份草稿：
   - 术语表草稿：术语 → 定义，及「应避免的同义词」。
   - 决策候选：仅当某决策同时满足「难回退 + 外人会疑惑 + 真实取舍」三条件时，才标为 ADR 候选。
7. **不贸然行动**：在用户明确确认「达成共同理解」之前，不写文件、不改代码、不执行任何动作。

### 3.2 按需落盘（核心改动）

仅当用户显式要求保存时执行，写到**当前工作目录**：

- **`CONTEXT.md`**（根目录）：统一语言/术语表，格式见 `references/CONTEXT-FORMAT.md`。
- **`docs/adr/NNNN-slug.md`**：每个敲定且达标的决策写一条 ADR，序号扫描 `docs/adr/` 现有最大号 +1，格式见 `references/ADR-FORMAT.md`。
- **懒创建**：没有术语就不建 `CONTEXT.md`；没有达标的决策就不建 `docs/adr/`。
- **可选纪要**：仅当用户额外要求「连过程也存 / 要纪要」时，生成 `docs/grill-summary.md`，记录关键问答与最终结论。

落盘位置、触发词（保存/落文档/导出）均以自然语言识别，不强制特定命令。

## 4. 文件结构

技能目录 `deep-discussion/` 内：

```
deep-discussion/
├── SKILL.md                    # 主技能：拷问循环 + 按需落盘指令（中文）
└── references/
    ├── CONTEXT-FORMAT.md       # 术语表格式（译自 Matt 原版，中文）
    └── ADR-FORMAT.md           # ADR 格式（译自 Matt 原版，中文）
```

说明：
- `SKILL.md` 的 frontmatter `name` 取 `deep-discussion`，`description` 用中文描述触发场景（打磨计划/设计、需要被「拷问」对齐时）。
- `references/` 下的两份格式文件直接复用原版结构、翻译为中文，保证产出文档与原版一致且可读。

## 5. 边界与错误处理

- **cwd 不可写 / 落盘失败**：提示用户并询问替代路径，不静默失败。
- **用户想重来**：支持「清空草稿 / 重启拷问」，丢弃内部累积的术语与决策草稿。
- **铁律**：除非用户明确要求，绝不自动创建任何文件——这是本技能相对原版最大的行为差异，必须严格执行。
- **多 context 仓库**：若检测到 `CONTEXT-MAP.md`，按原版逻辑推断应使用哪个 context；若无法确定则询问用户（参考 `CONTEXT-FORMAT.md` 中的多 context 说明）。

## 6. 验收标准

1. `/deep-discussion` 能启动一次结构化拷问：一次一问、带推荐答案、逐枝推进。
2. 纯聊天、用户不要求保存时，工作目录**不产生任何文件**。
3. 用户说「保存 / 落文档」后，在 cwd 生成 `CONTEXT.md`（有术语时）和 `docs/adr/`（有达标决策时），格式符合 references 规范。
4. 用户额外要求时，才生成 `docs/grill-summary.md`。
5. 全程中文，文档内容与原版语义一致。

## 7. 范围之外（YAGNI）

- 不引入子 agent / 多文件编排（方案 A 已排除）。
- 不做自动 PR、issue、Trello 等外部系统集成。
- 不主动维护 `CONTEXT-MAP.md` 多 context 体系，仅在检测到时正确响应。
- 不在未获要求时生成任何「过程记录」类文件。
